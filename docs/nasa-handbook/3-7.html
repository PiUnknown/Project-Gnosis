SECTION 3   ·   SUBSECTION 3.7
DOCUMENT GENERATION
3.7.1

INTRODUCTION.

The document generator is a pure function over state. It assembles the onboarding document section by section, produces a compact context document for a downstream AI assistant, serialises the complexity report, and writes a per-file explanation pair in Markdown and JSON. The one idea the reader must leave with is that every section is independently guarded: one failed section is omitted with a warning, and the remaining document is still returned (figure 3.7-1).

3.7.2

FUNCTIONAL DESCRIPTION.

run iterates the onboarding builders in a fixed order, appending each returned string. It then calls generate_agent_context_doc, which composes ten sections aimed at an AI coding assistant: overview, entry points, core components, relationships, high-risk areas, cycles, domain objects, change impact, safe starting points and AI explanations. The complexity report is serialised from the score objects. The per-file explanation document and JSON are produced by separate builders. Each of the four major outputs is wrapped in its own try block.

3.7.2.1

Degradation Rule.

Section builders that fail are skipped, not replaced by a placeholder, so a document can be missing a heading without any visible marker in the body. A failure of the whole agent-context builder substitutes a one-line error document. The API always returns whatever fields were produced; the CLI writes only the files that exist.
