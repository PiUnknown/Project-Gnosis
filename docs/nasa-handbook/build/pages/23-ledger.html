6.2.1

INTRODUCTION.

The repository carries three layers of description: the public README, the original specification, and the decision and change logs. They were written at different times and are not regenerated. Where they disagree with the code, this handbook follows the code and records the disagreement. The README is the most visible and the most stale; agent.md is the most current prose record; the decision log is the richest rationale but contains numbering faults (figure 6.2-1).

6.2.3

Records That Remain Useful.

agent.md is the best starting point for a code-aware reader: it was written against the current pipeline and lists its own known drift. Decisions.md remains valuable for rationale even where identifiers are duplicated, because each entry names the problem it solved. DESIGN.md describes a visual system that is largely present in index.css and App.tsx, but it is ignored by git and therefore not part of a clone. GLOSSARY.md and PROJECT_SPEC.md describe the intended vocabulary and original scope; they should be read as history.

WARNING

The README's deployment section names a workflow file that does not exist. A reader following it will look for the wrong path and may conclude deployment is unconfigured. The actual workflows are present under different names; their live status was not tested and is not asserted here.
