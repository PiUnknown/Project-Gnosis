7.2.1

INTRODUCTION.

The suite is broad, offline and fast: 476 cases in roughly twenty seconds. It is strongest on pure transformations and HTTP contracts, and weakest on the seams between stages. That shape is typical of a system built stage by stage: each agent has detailed unit tests, while the orchestration that connects them is covered only indirectly. Read a green run as evidence that the parts behave, not that the whole path has been exercised (figure 7.2-1).

7.2.2

FUNCTIONAL DESCRIPTION.

Unit tests build source strings, parse them and assert on dataclasses; they do not need a repository. API tests import the FastAPI application, replace the pipeline submission with a fake, and drive routes through TestClient. Store tests run the same lifecycle twice, once against the memory backend and once against fakeredis with WATCH semantics. The active-index tests simulate contention by mutating keys between a read and a write, and cover lost sentinels, external members and interrupted reconciliation.

The resilience tests are the most informative for an operator: partial model failure, missing collection, missing key, terminal-record protection and retry exhaustion all have explicit cases. Multi-language tests cover symbol extraction and complexity for Go, Rust, Java and C++, plus alias and layout resolution. Two cases assert that concurrent parsing and scoring return the same state as sequential execution.
