3.4.1

INTRODUCTION.

Complexity scoring assigns each source file one of four risk levels from independent structural signals: syntax failure, cycle membership, maximum function complexity, average complexity, coupling, undocumented ratio and line count. The one idea the reader must leave with is that the signals combine by OR, not AND. A file reaches the highest level any single signal justifies (figure 3.4-1).

3.4.2

FUNCTIONAL DESCRIPTION.

For Python, Radon's cc_visit returns per-function complexity; for JavaScript, TypeScript and the generic languages, the scorer walks the syntax tree and counts branch node types (if, loop, catch, ternary, logical operators, switch cases). Files are scored in a thread pool of up to twelve workers. Because coupling comes from the graph, which runs concurrently, the scorer first writes a provisional coupling count from symbol-table imports. apply_graph_coupling then replaces it with the graph out-degree, updates cycle membership, and recomputes the verdict for every file.

3.4.2.1

Verdict Rule.

The evaluator checks CRITICAL signals first and returns immediately when one fires. Otherwise it checks each HIGH signal, then each MEDIUM signal. Reasons accumulate, so a file can carry several explanations for one level. A clean file with no function and no signal is LOW with an empty reason list.

CAUTION

These are heuristics, not defects. A generated parser with a 25-branch switch is CRITICAL by rule even if it is correct. Use the level to choose what to read first, not as a quality judgement. The recorded reason text for CRITICAL max-CC is malformed; see 8.1-1.

3.4.4

WORKED READING.

A 720-line file with average complexity 4.0 and a worst function at 23 is CRITICAL, not HIGH: the evaluator returns on the critical signal before it tests line count. A worst function at 12 in the same file is HIGH twice over — the complexity and line-count reasons are both kept.
