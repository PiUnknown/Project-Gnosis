7.1.1

INTRODUCTION.

There are two deployment shapes and they differ in more than transport. The local shape runs the API in one process and executes jobs on a thread pool inside it. The distributed shape adds Redis and at least one worker process; the API only enqueues. Both share the same store interface and the same pipeline function. For reading or testing the codebase, the local shape needs no Redis and no model key if the LLM stage is skipped (figure 7.1-1).

7.1.2

FUNCTIONAL DESCRIPTION.

A CLI run needs an interpreter, dependencies, a GitHub address and, unless --skip-llm is passed, an NVIDIA key. It writes ten files into the output directory. An API run needs the same environment plus an HTTP client; when Redis is absent, the API executes the pipeline in a two-thread local pool. The frontend is independent: it needs Node, a build, and the API origin.

Environment is loaded from .env by python-dotenv in both entry points. Variable names below come from the example file only; no values were read for this handbook. A private repository requires a token, which is propagated per request and never persisted in a job record.
