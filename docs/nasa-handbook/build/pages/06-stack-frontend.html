2.1.4

INTRODUCTION.

The operator display is a single-page React application built by Vite and served as static files. It has one source file of consequence, App.tsx, holding the landing, progress, results and error screens plus an inline design system. The point to retain: navigation is local component state, not a router — react-router-dom is installed but never imported by the entry point (figure 2.1-3).

2.1.5

FUNCTIONAL DESCRIPTION.

main.tsx mounts the application inside a Sentry error boundary and a PostHog provider, then appends Vercel Analytics and Speed Insights. App.tsx submits {repo_url, max_explanations, skip_llm} to /api/analyze, stores the returned job identifier, and polls /api/jobs/:id every 1,500 milliseconds. When status becomes complete, it fetches /api/jobs/:id/result and renders six tabs: onboarding, agent context, explanations, dependency graph, complexity and raw JSON. The graph tab hands the full node and link arrays to a WebGL force layout. A reset returns the operator to the landing form; the error screen is declared and rendered but never set, so failures surface in the progress screen (defect D-16).

2.1.5.1

Build and Headers.

Vite builds static assets into dist/. Vercel serves them with a Content-Security-Policy and security headers from frontend/vercel.json, and proxies PostHog under /ingest and /decide. The same file rewrites unknown paths to index.html — conventional for a single-page application, unnecessary while the router is unused.
