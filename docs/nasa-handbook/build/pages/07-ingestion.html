3.1.1

INTRODUCTION.

Ingestion is the only stage that talks to GitHub. It obtains the complete path list for one branch, keeps the files that are worth reading, classifies the repository by size, and downloads the raw text of each kept file. It writes two large fields: a manifest of file metadata and a dictionary of path-to-text. The one idea the reader must leave with is that the manifest, not the repository, defines everything downstream; a file absent here cannot exist for later stages (figure 3.1-1).

3.1.2

FUNCTIONAL DESCRIPTION.

The stage calls fetch_file_tree once. For each entry it applies should_include_file, which checks directory segments first, then exact filenames, then minified suffixes, then the extension allow list, then the 150 KB ceiling. Surviving entries are sorted by slash count and then by path, so shallow files are preferred when a cap applies. The stage sets analysis_mode and calls fetch_file_contents_batch, which uses a shared requests session, a thread pool capped at sixteen, and five attempts with backoff. Line counts are computed from the returned text rather than trusted from the API.

3.1.2.1

Incremental Manifest Diff.

When state.is_incremental and a previous state exists, compute_manifest_diff classifies paths as added, modified, deleted or unchanged by SHA. Only changed paths are fetched; unchanged raw text is copied from the previous state when available. A deleted file is therefore visible to later stages as a diff entry, not as content.
