EXPLAINABILITY
3.6.1

INTRODUCTION.

Explainability is the only stage that calls a language model. It selects a bounded set of files, assembles code context from the vector index, builds a per-file prompt with structural metadata, and requests a short architectural explanation over an OpenAI-compatible endpoint. The one idea the reader must leave with is that selection, not generation, determines quality: only twenty files are explained by default, chosen by risk and import centrality (figure 3.6-1).

3.6.2

FUNCTIONAL DESCRIPTION.

run requires a collection name and an NVIDIA_API_KEY; without either it returns the state unchanged. It connects a CodeRetriever, reuses explanations for unchanged files in incremental mode, and sorts candidates by tier, then descending in-degree, then path. For each selected file it checks a SHA-keyed disk cache, assembles up to 8,000 characters of chunk text, builds the prompt, and calls the model with temperature 0.1 and an 800-token limit. Successful answers are stripped, stored in state and cached. A failure is counted and skipped; it does not abort the run.

3.6.2.1

Context Budget.

Context assembly orders the module chunk first, then function chunks by descending complexity, then class chunks. It accumulates until 8,000 characters. If fewer than 300 characters remain, it writes a count of omitted chunks instead of a fragment. Retrieved code is therefore always cut at a chunk boundary or marked as truncated, never silently.
