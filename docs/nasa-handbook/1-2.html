1.1.1

INTRODUCTION.

This handbook is the systems-data volume for the Project Gnosis code-archaeology system. It describes what the system is, how its nine subsystems work, the order in which they execute, every file that belongs to the repository, and the decisions that shaped them. The single idea the reader must leave with is that Gnosis is a deterministic seven-stage compiler wrapped around one hosted language-model call, not an autonomous agent swarm (figure 1.1-1).

The document is organised for three readers. An operator starts at section 7 and uses section 3 for fault isolation. A reviewer reads sections 1, 4 and 6. A maintainer reads section 3 in pipeline order, then section 5 for the file inventory. Section 8 records defects and unresolved questions so that no reader mistakes a known gap for an undocumented feature.

1.1.2

HOW TO USE THIS DOCUMENT.

The page number is the address. A reference such as 3.5-1 means section 3, subsection 3.5, sheet 1. Figure and table numbers run continuously inside a subsection. Paragraph numbers are stable and are used in the source-verification appendix.

Three marks qualify evidence. OBSERVED statements were read from source, configuration or test code in this working tree. DOCUMENTED statements come from a repository prose file, comment or commit message and were not exercised. INFERRED statements are conclusions; the basis is named in the sentence. A claim that cannot be placed in one of these classes is listed as an open item in 8.2-1.
